# Review Action Usage Guide Design

## Status

- Date: 2026-07-28
- Status: Approved
- Selected approach: 在“检验结论 / 气泡标记”之后增加横跨两列的折叠式“怎么选择？”说明。
- Scope: frontend presentation、copy、focused tests。

## Context

现有操作栏已经常驻显示：

- “排除”：不进入 SIP，也不生成气泡；
- “设为无需气泡”：仍进入 SIP，仅不生成图纸气泡。

这些文案说明了操作后果，但没有告诉审核人员在真实业务中如何判断。用户仍需要额外理解
“是否为有效检验要求”和“是否需要图纸定位”是两个不同问题。

## Goals

- 在产生歧义的操作附近提供可随时查看的审核判断规则。
- 解释“无需气泡”的典型适用场景以及“排除”的典型适用场景。
- 默认不增加明显高度，不把“内容调整”和后续操作长期推到更下方。
- 不改变既有 `exclude`、`set_balloon_required`、SIP、气泡、冻结或导出语义。

## Non-Goals

- 不新增全局帮助中心、首次引导、toast、modal 或用户偏好。
- 不根据检验项类型自动替用户选择“排除”或“无需气泡”。
- 不改变两个按钮的 command payload、确认流程或 disabled 条件。
- 不修改 backend、API、schema、reviewed result 或 export。

## Placement And Interaction

说明挂载在 `ReviewPanel` 的 `review-command-rail` 内：

1. “检验结论”和“气泡标记”继续占据第一行两列；
2. 排除确认块存在时继续紧跟第一行动作；
3. “怎么选择？”横跨两列，位于第一行动作或排除确认块之后；
4. “内容调整”位于说明之后。

使用原生 `details / summary`：

- 默认关闭，只显示一行“怎么选择？”；
- 点击或键盘激活后展开；
- 再次激活后收起；
- 不持久化打开状态，不产生业务 command，也不改变当前检验项。

## Copy

折叠标题：

`怎么选择？`

展开后的引导句：

`先判断这条内容是否仍是有效检验要求。`

“无需气泡”说明：

`仍是有效检验要求，需要进入 SIP；仅不在图纸上生成气泡。常见于整体要求、通用标准、材质或表面处理等没有唯一标注位置的要求。`

“排除”说明：

`不是有效检验要求，不进入 SIP，也不生成气泡。常见于 OCR 误识别、图框或标题文字、无效重复项以及无需检验的内容。`

说明只解释选择规则，不替代两个按钮下方现有的简短后果文案。

## Visual Treatment

- 折叠标题使用现有工程蓝作为可交互提示，不新增图标依赖。
- 展开内容使用浅蓝背景、现有边框色和小号正文，保持工业软件的轻量说明层级。
- 说明容器横跨操作栏两列，不嵌套新的重型卡片、阴影或渐变。
- 在约 `293px` 的真实详情宽度中保持单列文字，不产生横向滚动。

## Accessibility

- 使用原生 `summary`，保留浏览器的键盘和展开状态语义。
- “无需气泡”和“排除”分别使用可读标题，不依赖颜色区分。
- 折叠说明不抢焦点，不改变排除确认块现有的焦点进入与返回行为。
- 审核冻结或保存期间仍允许阅读说明；`disabled` 只继续约束业务按钮。

## Verification

### Component Tests

- 默认显示“怎么选择？”，详细说明未展开。
- 激活 summary 后，两类判断规则和典型例子可见。
- “排除”和“设为无需气泡”的既有按钮、帮助文案和 command 行为保持不变。
- 排除确认块与使用说明同时存在时，确认块仍紧邻动作且焦点行为不变。

### Browser Smoke

- 在现有本地真实项目中选择一个检验项。
- 确认折叠标题位于两组动作之后、“内容调整”之前。
- 展开后确认完整说明可读，操作栏无横向溢出。
- 收起后确认面板恢复紧凑高度。
- 确认 console 没有新增 error 或 warning。

### Build

- 运行完整 frontend test suite。
- 运行 frontend production build。
